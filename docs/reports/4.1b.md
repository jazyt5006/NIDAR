### Effect of the default pose covariance in the simulator (item 2)
The simulator's static scenes publish poses without covariance, so the messages carry an all-zero (unknown) covariance. 5 seeds, offset 0.0, default off vs on
(`docs/reports/4.1b_cov_default.txt`, script `ros2/survivor_tagging_ros/tools/cov_default_effect.py`):

| scenario | tags | mean top-cell p off -> on | mean sigma_h m off -> on | CONFIRMED off -> on | correct cells (any status) |
|---|---|---|---|---|---|
| standing | 5 | 0.759 -> 0.725 | 0.166 -> 0.177 | 1 -> 1 | 5/5 -> 5/5 |
| sitting | 5 | 0.784 -> 0.748 | 0.153 -> 0.166 | 2 -> 2 | 4/5 -> 4/5 |
| near_wall | 5 | 0.938 -> 0.900 | 0.166 -> 0.177 | 5 -> 3 | 5/5 -> 5/5 |
| tilt_30 | 5 | 0.798 -> 0.759 | 0.199 -> 0.212 | 0 -> 0 | 3/5 -> 3/5 |
| two_adjacent | 10 | 0.818 -> 0.801 | 0.169 -> 0.180 | 4 -> 4 | 8/10 -> 8/10 |
| cell_boundary | 5 | 0.872 -> 0.803 | 0.167 -> 0.178 | 3 -> 2 | 0/5 -> 0/5 |
| revisit_after_gap | 5 | 0.890 -> 0.890 | 0.083 -> 0.083 | 4 -> 4 | 3/5 -> 3/5 |

Reading: the default lowers the mean top-cell probability by about 0.03 (0.835 -> 0.803 over all rows) and widens the horizontal sigma by about 1 cm; it
costs two CONFIRMED tags (near_wall, cell_boundary) and changes no cell. revisit_after_gap is unchanged because the simulator gives those poses a covariance.
This only says how much probability mass moves when "the pose is exact" is replaced by 0.10 m / 0.05 rad; it does not validate the values (they are ASSUMPTIONS until
the pose source is known, question S1).

## Ambiguities and how they were handled
- **Telemetry cadence.** The library's `TelemetryScheduler` already implements the 5 s snapshot and the 1 s per-tag update limit; the runtime forwards its messages as
  `TelemetryPacket` payloads instead of re-implementing them. Values come from the freeze file (tested).
- **Pose revision.** `max(counter + 1, event revision)` so live poses never carry an older revision than the last applied event even if the SLAM numbers have gaps.
- **Stamp 0.** The simulator starts at stamp 0, which the adapters reject as "unset"; test and smoke streams are shifted by 1 s (direct and message runs compare equal).
- **AC1 and the covariance default.** Simulator poses have no covariance and the direct pipeline uses none; AC1 therefore disables the default (`None, None`).
  The default is tested separately.
- **Unset alignment.** If `depth_aligned_to_color` is unset in the node but the overrides file sets `cam.detections_use_depth_aligned_frame`, the library value is used;
  unset in both is an error.
- **Runbook overrides.** The example override file does not match the simulator scenes, so the runbook uses `smoke_test --write-sim-overrides` (SIMULATION values).
- **Parameters typed dynamically.** The node declares parameters with `dynamic_typing=True` so that `"UNSET"` strings and YAML booleans both work; and `T_body_camera`
  uses a one-element list as "unset" because an empty list is awkward in rclpy. Both are unverified on Humble/Jazzy.
- **bytes for `uint8[]`.** `convert.py` assigns `bytes` to `sequence<uint8>` fields; whether every distro's generated class accepts it is unverified (flagged in the runbook).
- **Not implemented:** `use_sim_time` is the native ROS parameter (nothing coded); no persistence; no depth-image resampling (only box scaling, from 4.1a).
