## Ambiguities and how they were handled
- **Covariance "reorder".** The ROS order (x, y, z, rotation about fixed x, y, z) is the library layout, so the mapping is a reshape;
  FRD/FLU does not change it (a fixed-frame perturbation is unaffected by right-multiplying the body axes). Tested with a non-diagonal
  example. All-zero or `cov[0] == -1` = unknown (None), because a zero covariance would claim a perfect pose.
- **FRD body in an ENU world.** Their README says FRD body and ENU world; FRD normally goes with NED. The adapter converts the body
  axes only. Flagged in the handoff as a question for the SLAM owner.
- **pose_revision** is not in ROS pose messages; the caller supplies it (node: +1 per applied correction). ASSUMPTION, needs S4.
- **Detection timestamp.** Their ISO-8601 timestamp may be inference time; the message requires the image header stamp. The adapters
  reject zero / negative / malformed / non-monotonic stamps but cannot detect a consistently late stamp.
- **Detection image size vs depth size.** The library requires them equal, so the adapter scales the box when depth is aligned to
  colour and both scale factors agree; otherwise DEPTH_FRAME_MISMATCH.
- **Extra files:** `CandidateCell.msg` (cleaner than parallel arrays) and the full `GridRegistration` field set in `SetGridRegistration`
  (cell size, extent, index base, numbering are needed to build a registration).
- **Size estimate** uses my own XCDR1 estimator, not rosidl; treat it as +-10 %.
